## 2. N-gram language model (val perplexity, lower is better)

Trained on 472,547 train reports after abbreviation expansion; same vocabulary for all rows (train words seen once -> `<UNK>`), so the numbers are comparable.

| model | smoothing | val_perplexity | fit_s |
|---|---|---|---|
| 1-gram | Laplace | 862.2 | 8 |
| 2-gram | Laplace | 408.9 | 17 |
| 3-gram | Laplace | 2834.3 | 32 |
| 1-gram | Kneser-Ney | 863.8 | 8 |
| 2-gram | Kneser-Ney | 76.9 | 18 |
| 3-gram | Kneser-Ney | 41.2 | 38 |

Laplace gets *worse* as the order grows: with a vocabulary of tens of thousands, adding 1 to every unseen trigram steals most of the probability mass. Kneser-Ney discounts seen counts a little and backs off to lower orders, so the trigram's extra context actually helps.

## 3. Spelling correction

**Synthetic test:** 4,000 val reports, one real word per report corrupted by one random edit (delete / insert / substitute / swap). The corrector sees the typo in its real context and must recover the original word. The edit penalty is tuned on the first 2,000 cases and accuracy is reported on the other 2,000.

Tuning grid (tune half):

| edit_penalty | tune_accuracy_% |
|---|---|
| 1.0 | 92.5 |
| 2.0 | 94.6 |
| 4.0 | 96.4 |
| 6.0 | 97.1 |
| 8.0 | 98.0 |
| 10.0 | 98.6 |
| 15.0 | 98.8 |
| 25.0 | 98.8 |

Held-out half:

| method | held_out_accuracy_% |
|---|---|
| edit distance only (ties -> most frequent) | 96.7 |
| noisy channel: edit + trigram LM (penalty 15.0) | 99.2 |

The language model adds +2.5 points: context helps choose between candidates at the same edit distance. The config uses edit_penalty = 15.0.

Caveat: synthetic single-edit typos are easier than real ones (real typos are often 2+ edits or split/merged words), so these accuracies are an upper bound.

## 4. Early ablation (preliminary; final numbers in Phase 4)

TF-IDF (word 1-2 grams) + logistic regression (balanced class weights), ATA top-15 + OTHER. Trained on a random 100,000-report train sample, scored on the full 2024 val year. Input is the **whole masked report** (problem + action); Phase 4 uses the problem part only, so absolute numbers will change.

| input | unigram_vocab | val_macro_F1 | val_accuracy | fit_s |
|---|---|---|---|---|
| masked raw (tokenised only) | 16545 | 0.8551 | 0.8923 | 48 |
| + abbreviations | 16423 | 0.8542 | 0.8934 | 46 |
| + abbreviations + spelling | 16519 | 0.8529 | 0.8929 | 44 |
| + abbrev + spelling + Porter stem | 14270 | 0.8546 | 0.8931 | 40 |
| + abbrev + spelling + WordNet lemma | 15340 | 0.8543 | 0.8932 | 44 |

**Finding:** all variants are within 0.002 macro-F1 of each other. For a linear TF-IDF model trained on 100k reports, normalisation does not measurably help classification: each spelling variant is frequent enough to get its own weight, and stemming/lemmatisation only shrinks the vocabulary. Normalisation is expected to matter more where vocabulary mismatch hurts directly: BM25 retrieval of short technician queries (measured in Phase 5) and the Word2Vec/BiLSTM model (Phase 4).
