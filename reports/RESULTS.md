# AeroFix: final results

Generated by `python -m aerofix.eval.final` (add `--full` to re-run every phase from raw data first). All numbers are on the **2025 test year** unless stated; every model choice was made on 2024 (val). Per-phase details: `reports/eda.md`, `normalisation.md`, `segmentation.md`, `classification.md`, `retrieval.md`, `recommend.md`, `rag.md`, `feedback_loop.md`.

## 1. Data

FAA Service Difficulty Reports 1995-2025, filtered to the A320 family and Boeing 737: 567,350 reports -> 540,008 after removing 27,311 duplicates (11,924 were later-year copies that would have leaked across splits). Time-based split: train <= 2023 (472,547), val 2024 (34,178), test 2025 (33,283). The raw 2025 counts match the project brief exactly (67,652 rows; 22,935 B737; 12,415 A320; 38 chapters; 347 JASC codes).

### 4b. Why character n-grams use tokenised text

Earlier run with character n-grams on the *raw* problem text. Normalised inputs looked +2 points better, but the 'tokenised only' control shows almost all of that gain comes from dropping punctuation before the character n-grams, not from abbreviation expansion or spelling correction. The final pipeline therefore tokenises first.

## 4. Text normalisation (Phase 2, val)

### Language model

Trained on 472,547 train reports after abbreviation expansion; same vocabulary for all rows (train words seen once -> `<UNK>`), so the numbers are comparable.

| model | smoothing | val_perplexity | fit_s |
|---|---|---|---|
| 1-gram | Laplace | 862.2 | 8 |
| 2-gram | Laplace | 408.9 | 17 |
| 3-gram | Laplace | 2834.3 | 32 |
| 1-gram | Kneser-Ney | 863.8 | 8 |
| 2-gram | Kneser-Ney | 76.9 | 18 |
| 3-gram | Kneser-Ney | 41.2 | 38 |

Laplace gets *worse* as the order grows: with a vocabulary of tens of thousands, adding 1 to every unseen trigram steals most of the probability mass. Kneser-Ney discounts seen counts a little and backs off to lower orders, so the trigram's extra context actually helps.

### Spelling correction

**Synthetic test:** 4,000 val reports, one real word per report corrupted by one random edit (delete / insert / substitute / swap). The corrector sees the typo in its real context and must recover the original word. The edit penalty is tuned on the first 2,000 cases and accuracy is reported on the other 2,000.

Tuning grid (tune half):

| edit_penalty | tune_accuracy_% |
|---|---|
| 1.0 | 92.5 |
| 2.0 | 94.6 |
| 4.0 | 96.4 |
| 6.0 | 97.1 |
| 8.0 | 98.0 |
| 10.0 | 98.6 |
| 15.0 | 98.8 |
| 25.0 | 98.8 |

Held-out half:

| method | held_out_accuracy_% |
|---|---|
| edit distance only (ties -> most frequent) | 96.7 |
| noisy channel: edit + trigram LM (penalty 15.0) | 99.2 |

The language model adds +2.5 points: context helps choose between candidates at the same edit distance. The config uses edit_penalty = 15.0.

Caveat: synthetic single-edit typos are easier than real ones (real typos are often 2+ edits or split/merged words), so these accuracies are an upper bound.

## 9. Feedback learning loop

![learning curve](learning_curve.png)

- **Part condition:** feedback +0.0245 macro-F1 vs the control (+0.0156 vs the deployed model). Condition codes drift between years (Phase 4: OTHER grows from 15% of train to 24% of test), and only the feedback carries the newer usage.
- **ATA chapter:** feedback -0.0016 vs the control: no measurable effect. The chapter classifier is already at ~0.86 and chapter labels do not drift, so extra recent examples add little; both updated models move by < 1 point (noise level for 2,000 queries).
- **Retrieval Hit@5:** +0.0245 from adding the feedback reports to the index alone; fine-tuning the bi-encoder on feedback triples adds +0.0015. Most of the benefit of feedback for retrieval is simply having recent, similar cases to find.

**Takeaways.** Most mistakes are not model failures in the usual sense: structure at system boundaries (center wing box, wheel wells, door surrounds) is coded inconsistently by reporters, some reports use operator-specific conventions, and a few labels look wrong. Genuine model errors are keyword bias (DOOR, WING pulling predictions) and missing domain knowledge (floor-path lighting in a 'transition strip'). One error comes from Phase 3 segmentation cutting the problem text at 'REPAIR'.

## 11. Limitations

- **No OEM manuals.** Airbus/Boeing AMM, SRM, FIM and TSM content is proprietary and was not used. AeroFix only points to references technicians cited in public reports; RAG passages come from generic FAA handbooks, which rarely match a specific aircraft system (e.g. door dampers).
- **US operators only.** FAA SDRs are filed by US operators and repair stations, so fleets, reporting habits and vocabulary are US-specific; transfer to other regions is untested.
- **Proxy labels.** Retrieval relevance (same JASC + condition) and action/reference hits are proxies for usefulness. A 50-query LLM check agreed with the retrieval proxy on only 63% of pairs; no large human-judged set exists.
- **Silver segmentation labels.** 399 of 400 problem/action annotations were made by a local LLM; segmentation scores measure agreement with those labels, not human gold.
- **Label noise in the source.** The same location can be coded to different ATA chapters by different reporters (see error analysis), which caps achievable accuracy.
- **Drift.** Part-condition codes drift across years (OTHER: 15% of train vs 24% of 2025); the feedback loop shows periodic updates are needed.
- **LLM latency and judgement.** The full Qwen 7B summary takes ~5-6 s (streamed); automatic checks catch invented citations/references but not subtle misreadings, so faithfulness still needs human scoring.
- **Decision support only.** AeroFix must never replace approved maintenance data or engineering judgement.
